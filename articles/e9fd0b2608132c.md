直近３回の記事では、**複数要素への同時可変参照**を構造的に許容するように設計されたアリーナアロケーターである[`ordex`についての解説](https://zenn.dev/rhetro/articles/c08b2a3eec8488)と、それを用いた[Boidsの実例](https://zenn.dev/rhetro/articles/0bbe700e5ec878)、そして、Ordexが内部でどうメモリーを処理してるかを[WASMで実装し可視化した](https://zenn.dev/rhetro/articles/a9a5a250c0aa0d)という内容でした。

今回は、AxiomaやZan-sortなどで動的計算を構造や静的トポロジーへ還元するという構造的アプローチを、DAGの実行基盤へと適用した[`Ordag`](https://github.com/rhetro/ordag)というCrateについてまとめます。

OrdagというDAG（有向非巡回グラフ、Directed Acyclic Graph）の実行エンジンのクレートは、[Ordex](https://github.com/rhetro/ordex)の`align!`（$N \le 16$）と`ordex()`($N > 16$)によるNode（点）の複数要素に対する同時可変参照（メモリalias）の解決に加え、`ordag::compile()`によるDAG経路（線）のRead/Write調停（構造alias）の２つの動的計算が静的トポロジーへ還元するという手法を組み込み、DAGの安全性をランタイム検証から消しつつ、その安全性を数学的に証明したDAGエンジンとして完成させたものです。

Ordagの機能を用いることで、DAGに内在する経路の依存関係探索とRead/Write調停という動的計算を、静的トポロジーとStream IDによる決定論的構造へ還元することで、実行時の探索・同期・衝突検証を構造的に消去することが可能になります。

## 1. DAGにおける動的計算の物理的制約

DAGの依存関係解決において、`Rc<RefCell>`や`Mutex`を用いた実行時の借用調停（動的計算）は、非線形システムにおける不可避の物理的ボトルネックです。

通常の実行モデルでは、入次数の更新やノードの探索といったランタイムコストがRustのBorrow Checkerの制約と衝突します。

この制約を根本から突破するためには、「点のalias（Ordex）」と「線のalias（Ordag）」の問題を分離し、ノード間の依存関係（線）と実際のストリーム（Stream）をまったく別の構造として扱う必要があります。

## 2. 依存関係（線）とストリームの構造的分離

`Ordag`は、依存関係の線とストリームを構造的に分離し、`TopologyRules`という事前契約によってグラフのアクセスルールすべてを静的なトポロジーとして確定させます。

`mutable_input_indices`や`read_input_indices`といった設定は、ストリームに対する読み書きの干渉をメモリ空間上で固定する構造的な意味を持ちます。

Stream IDによる起源追跡と、グラフをAppend-only（追加のみ）とするモデルによるトポロジーの単調性が、実行前の安全性を数学的に証明する基盤として機能します。

具体的には、ユーザーは以下のようにドメインのルールを事前契約として定義します。

```rust
// エンジンにグラフのトポロジールール（契約）を教える
impl TopologyRules for MyOp {
    fn mutable_input_indices(&self) -> &[usize] {
        match self {
            Self::Generator { .. } => &[],
            Self::Multiplier { .. } => &[0], // 0番目の入力をインプレースで更新（Write）する
        }
    }
    fn read_input_indices(&self) -> &[usize] { &[] }
    fn expected_input_count(&self) -> usize {
        match self {
            Self::Generator { .. } => 0,
            Self::Multiplier { .. } => 1,
        }
    }
}
```

## 3. Kahnアルゴリズムの静的化と層構造の決定論的生成

`OrdagEngine`は、通常は実行時に行われるトポロジカルソート（Kahnのアルゴリズム）をコンパイル時の「静的な構造生成」として実行し、安全な層（Layer）を決定論的に構築します。

トポロジカルソートとは、DAGにおける各Nodeの処理順序を破綻なくスケジューリングするアルゴリズムです。

Ordagではこれをランタイムに行うのではなく、グラフ構築時の`compile()`関数によって経路を完全に確定させます。

レイヤーを生成する過程でStream IDが伝播し（Generatorノードは新規ストリーム生成、Mutatorノードは親の継承）、Write-WriteやRead-Writeの衝突が静的に検証されます。

ここで構造的なalias（競合）が検出された場合はFail-fastによって即座にパニックし、検証を通過した層構造だけが安全な並列実行計画として出力されます。

## 4. 点と線のalias調停を層トポロジーへ還元し、実行時コストを完全消去

`Ordex`（点）と`Ordag`（線）によって2つのaliasが共に静的なトポロジーへ還元されることで、実行ループ内におけるBorrow Checkerの動的な検証コストは構造的に完全に消滅します。

`Ordex`による点のalias（複数要素への同時可変参照）の解決を土台とし、`Ordag`の`compile()`は、実行前フェーズですべてのStream IDの依存関係を静的に証明します。

これにより、同じストリームに対して「同時に書き込もうとしていないか（Write-Write競合）」「読み込み中に書き込もうとしていないか（Read-Write競合）」が構造的に排除されます。

実行フェーズにおける探索・同期・衝突検証が一切不要になるため、この2つのクレートの組み合わせは、10,000ノードの連続処理であってもL1/L2キャッシュ帯域の物理限界（帯域飽和）まで極限性能を引き出します。

**10,000ノードの直列変異チェーンにおけるベンチマーク（Releaseビルド）**
* **構築フェーズ（静的証明と層生成）**: 約 8.9 ms（$O(N+E)$ の静的解析）
* **実行フェーズ（インプレース更新）**: 約 2.5 ms（1ノードあたり 0.25 µs、純粋なメモリ帯域速度）

実際の実行ループは以下のように、ランタイムチェックの一切ないゼロアロケーションのバッチ更新として記述されます。

```rust
// 事前に静的エイリアス証明とレイヤー構築を完了させる
engine.compile();

// 数学的に安全が証明された層（Layer）ごとに処理を進行
for layer in &engine.execution_layers {
    let mut multi_batch = Vec::new();
    // ... 各ノードのコマンドをパースして multi_batch に登録 ...

    // Ordexを用いたゼロコストのインプレース・バッチ更新
    if !multi_batch.is_empty() {
        multi_batch.sort_unstable_by(|a, b| a.0.index.cmp(&b.0.index));
        let targets: Vec<Index> = multi_batch.iter().map(|(idx, _)| *idx).collect();
        
        // エイリアス不在を空間的に確定
        let verified = VerifiedIndices::new(targets);
        let factors: Vec<_> = multi_batch.into_iter().map(|(_, f)| f).collect();

        // Borrow Checkerの動的検証なしで一括更新
        buffers.ordex(&verified, move |mut iter| {
            for factor in factors {
                let buf = iter.next().unwrap();
                for val in &mut buf.data {
                    *val *= factor;
                }
            }
        });
    }
}
```

## 5. 構造的決定論への収束
Ordagは、Axioma、Zan-sort、Ordexと連なる「動的計算の静的トポロジーへの還元」という系列において、線のaliasを層トポロジーへ還元する計算基盤です。

階層構造を座標空間へ還元するAxioma、比較を幾何ルーティングへ還元するZan-sort、点のaliasを空間トポロジーへ還元するOrdexに続き、Ordagは依存関係（線）のaliasを層構造として確定させることで、非線形システムの実行モデルを構造的決定論へと収束させます。

この構造的還元の本質は、非線形システムに不可避とされてきた「時間的調停（スレッド同期やロック）」を、数学的に証明された「空間的配置（層）」へと完全に変換した点にあります。実行時の状態監視をトポロジーの確定へと置き換えることで、安全性と極限性能のトレードオフが構造的に消去されます。
