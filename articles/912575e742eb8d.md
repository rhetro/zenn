１つ目の記事では、Crate群全体を貫く構造的哲学として、「ランタイムコストを静的なコンパイル時コストへの転嫁」について書きました。

２つ目の記事では、具体的な`Axioma`というCrateを例に挙げ、「データ構造の静的空間投影」によるランタイムコストの消去について書きました。

今回の記事のテーマは、`Zan-sort`というCrateの「計算を構造へ還元する」というコンセプトについてです。

**Zan-sortは、比較という動的計算を捨て、順序付けを幾何構造へ還元することで、ソートを「空間的ルーティング問題」へと変換するエンジンです。**


## 1. 比較構造からの脱却（動的計算の排除）

プログラミング言語におけるソートは、原則として「比較評価」を前提とした動的計算モデルの上に成り立っています。

Rustにおいても、標準のソートアルゴリズムである`std::sort_unstable`は、`Ord`トレイトがベースとなっているため、実行時に要素同士を比較し、その結果に基づいて分岐・再配置を行うというプロセスが存在します。

しかし、この「比較」という行為自体が、データ量に比例してCPUの分岐予測やメモリ階層を圧迫し続ける純粋なランタイムコストとして蓄積されていきます。実行時に要素同士を比較し合うという「動的計算」のパラダイムに留まる限り、ハードウェアの性能を極限まで引き出すことは不可能です。

Zan-sortは、この動的計算を根底から放棄します。`std::cmp::Ord` トレイトへの依存を完全に捨て、すべてのデータを単一の絶対的な値（`u64 SortKey`）として定義し直します。これにより、「要素間の比較」という動的な状態管理は完全に消去されます。


## 2. 幾何構造への還元（空間への投影）

比較という動的計算を排除した瞬間、順序付けは「評価」ではなく「空間への投影」へと構造的に転換されます。Zan-sortは、順序付けをアルゴリズムではなく、事前に確定した幾何構造（Execution Geometry）として扱います。

動的精度スケーリング（Dynamic Precision Scaling）とプレフィックス・サム（Prefix-sum）によって事前にキースペースを計算することで、メモリアドレス上に「完全に重複しない（Disjointな）書き込み領域」を幾何学的に確定させます。

ここで行われるのは、一般的な非比較ソート（Radix Sortなど）のような複数回のパスを用いたヒストグラム構築やバリア同期ではありません。

Zan-sortが行うのは、**「Single-Pass Disjoint Routing（単一パスの素なルーティング）」**です。各スレッドは、共有された状態（Shared Mutable State）、アトミック操作、ロックなどを一切持たず、ただ物理的に分割された座標へ向かってデータを散布（Scatter）するだけです。

順序付けは「実行時の比較や調停」ではなく、純粋な「静的座標へのポインタ追跡と配置」という幾何構造へと完全に還元されます。


## 3. 帯域飽和という物理法則（ハードウェアへの帰結）

計算が幾何構造へ還元されると、プログラムのスループットはアルゴリズムの複雑性ではなく、DRAM帯域という物理法則に完全に支配されます。つまり、Zan-sortの速度は「高速化の結果」ではなく、「構造変換の物理的帰結」です。

この「比較構造 → 幾何構造 → 帯域飽和」という構造的転換は、そのまま圧倒的な物理的スコアとして現れます。

実測値として、1億（100M）要素のソートにおいて、Zan-sortは8コア環境で **678ms** を記録しました。

**【並列アーキテクチャ・スケーリング（1億要素 / 8コア制限）】**

| 計算モデル | パラダイム | 実行時間 | Rayon比 |
| :--- | :--- | :--- | :--- |
| `rayon::par_sort_unstable` | Parallel Compare | 954 ms | 基準 |
| `parallel_radix_sort` | Parallel MSD Radix | 1.33 s | - 39.4% |
| **`zan-sort`** | **Disjoint Parallel Routing** | **678 ms** | **+ 28.9%** |

また、シングルスレッド環境での絶対スループット比較においても、500万（5M）要素で **34.8ms** を記録し、標準ライブラリ（154.8ms）を圧倒的に凌駕しています。

**【絶対スループット比較（シングルスレッド / 各要素数）】**

| 要素数 (N) | `std::sort_unstable` | Radix Sort (Base 256) | `zan-sort` |
| :--- | :--- | :--- | :--- |
| 16 | 342 ns | - | 279 ns |
| 64 | 733 ns | - | 735 ns |
| 1,000 | 15.69 µs | - | 15.80 µs |
| 5,000 | 91.17 µs | - | 91.07 µs |
| 10,000 | 194.43 µs | - | 184.95 µs |
| 5,000,000 | 154.80 ms | 118.91 ms | **34.80 ms** |
| 100,000,000 | 3.49 s | 2.16 s | **683.4 ms** |

ここで強調すべきは、Zan-sortが「既存のアルゴリズムより巧妙にチューニングされたソフトウェア」ではないということです。

この速度は、順序付けという計算モデルを空間的ルーティングへと変換し、ハードウェアの物理境界と完全に同期させた結果として、必然的に現れた物理法則の観測結果に過ぎません。


## 4. 構造計算モデルの射影系列（統一原理）
Zan-sortにおけるこのアプローチは、単なる独立した最適化のテクニックではありません。これらの最適化は、現在構築している一連のCrate群を貫く、**「構造計算モデルの射影系列」**の一部です。

前回の記事で解説したAxiomaが、「データ表現」において階層構造をコンパイル時の**「座標空間」**へと投影するものであったのに対し、今回のZan-sortは、「メモリ実行」において比較という動的計算を**「幾何空間へのルーティング」**へと投影しています。

対象とするドメインこそ異なりますが、これらはすべて「動的計算を構造へ還元する」という単一原理の異なる投影に過ぎません。

計算をアルゴリズムや実行時の状態管理としてではなく、構造・幾何・トポロジーとして再定義すること。Rustという言語の厳格な制約に対するひとつのハックとしてではなく、計算そのものの新しい表現形式として、この一連の構造的アプローチが持つ可能性を感じていただければ幸いです。
